# Receiving Relayfile Webhooks

Relayfile webhook subscriptions deliver workspace events to your HTTPS endpoint.
Create, list, and delete subscriptions at
`/v1/workspaces/{workspaceId}/webhooks`. The subscription secret is generated by
Relayfile and returned only in the create response. Store it securely when the
subscription is created.

## Verify every delivery

Every outbound delivery includes these headers:

- `X-Relay-Signature`: lowercase hexadecimal HMAC-SHA256 digest, with no prefix
- `X-Relay-Timestamp`: Unix time in seconds, encoded as a string
- `X-Relay-Event-Id`: stable identifier for this event

The signed message is the timestamp, a literal period (`.`), and the raw request
body exactly as received:

```text
timestamp + "." + rawBody
```

Use the per-subscription secret as the HMAC key. Do not parse and re-serialize
the JSON before verification; even semantically equivalent JSON can have
different bytes. Compare the expected and received digests in constant time,
and reject timestamps outside a replay window chosen for your service.

This Node.js/Express example uses a five-minute replay window as an example
receiver policy. `processOnce` must use durable storage and apply the event's
effects idempotently (or transactionally with a unique event-ID record) so
deduplication also works across restarts and multiple receiver instances.

```js
import crypto from "node:crypto";
import express from "express";

const app = express();
const MAX_AGE_SECONDS = 5 * 60;

app.post("/relayfile", express.raw({ type: "application/json" }), async (req, res) => {
  const signature = req.get("X-Relay-Signature");
  const timestamp = req.get("X-Relay-Timestamp");
  const eventId = req.get("X-Relay-Event-Id");

  if (!signature || !timestamp || !eventId || !/^\d+$/.test(timestamp)) {
    return res.sendStatus(400);
  }

  const now = Math.floor(Date.now() / 1000);
  const sentAt = Number(timestamp);
  if (!Number.isSafeInteger(sentAt) || Math.abs(now - sentAt) > MAX_AGE_SECONDS) {
    return res.sendStatus(401);
  }

  const expected = crypto
    .createHmac("sha256", process.env.RELAYFILE_WEBHOOK_SECRET)
    .update(`${timestamp}.`, "utf8")
    .update(req.body)
    .digest();

  if (!/^[0-9a-f]{64}$/.test(signature)) {
    return res.sendStatus(401);
  }
  const received = Buffer.from(signature, "hex");
  if (!crypto.timingSafeEqual(expected, received)) {
    return res.sendStatus(401);
  }

  await processOnce(eventId, () =>
    handleRelayfileEvent(JSON.parse(req.body.toString("utf8"))),
  );
  return res.sendStatus(204);
});
```

Relayfile delivery is at-least-once, so receivers **must** deduplicate using
`X-Relay-Event-Id`. Commit the event ID and its business effects atomically when
possible; otherwise make the effects idempotent and record success only after
processing completes. Return a 2xx response promptly; redirects and every other
3xx or greater status count as failed delivery attempts.

## Retries and dead letters

Each event gets at most three delivery attempts. A delivery attempt times out
after five seconds. Failed attempts use exponential backoff starting at 10
seconds and then 20 seconds, capped at 600 seconds, with plus or minus 20%
jitter. After the third failed attempt, Relayfile moves the delivery to the
webhook delivery dead-letter queue (DLQ).

Retry intervals are computed when each retry is scheduled and are not persisted.
The DLQ record retains the final `failedAt` timestamp, not an attempt-by-attempt
schedule. Operators can inspect and replay failed deliveries with:

```text
GET  /v1/workspaces/{workspaceId}/webhooks/dlq
POST /v1/workspaces/{workspaceId}/webhooks/dlq/{deliveryId}/replay
```

Replaying a delivery can produce another copy of an event the receiver already
processed. The `X-Relay-Event-Id` deduplication rule therefore applies to both
automatic retries and manual replays.

## Do not use the internal ingress scheme

Outbound partner webhooks and Relayfile's internal ingress both use a header
named `X-Relay-Signature`, but they are different protocols:

| Direction | Signing key | Signed message |
|---|---|---|
| Relayfile to a subscription endpoint | Per-subscription secret | `timestamp + "." + rawBody` |
| Internal ingress to Relayfile | `INTERNAL_HMAC_SECRET` | `timestamp + "\n" + body` |

Receiver integrations must use the outbound subscription scheme. The internal
newline-delimited scheme and `INTERNAL_HMAC_SECRET` are only for trusted
relay-cloud-to-relayfile ingress and must not be exposed to partner receivers.
